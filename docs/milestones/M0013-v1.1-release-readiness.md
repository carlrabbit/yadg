## Target framework and platform decision

### Selected package TFM

Keep:

```text
net10.0
```

with:

```text
PlatformTarget = x64
```

Do not switch to `net10.0-windows` merely because the product contains a Word renderer.

The portable TFM is intentional: Office-independent authoring and CLI surfaces should not be compile-time blocked solely by the Word specialization.

### Support claim

YADG 1.1 remains:

```text
Windows x64 — authoritative supported/validated full-product locus
```

The portable TFM does **not** constitute a promise that every renderer/runtime combination is supported on every .NET 10 platform.

### Required Word runtime guard

The Word renderer must detect non-Windows execution before:

- `Thread.SetApartmentState`;
- COM activation;
- any Windows-only runtime operation.

On non-Windows, a direct request for:

```text
yadg render --renderer word
```

must fail with an actionable normal YADG diagnostic and non-zero command result.

It must not surface an uncaught:

```text
PlatformNotSupportedException
COMException
TypeInitializationException
```

or equivalent runtime crash.

The guard should live at the renderer/product boundary, not depend solely on TFM analyzer annotations.

YOLO may then try LibreOffice according to the existing resilience contract if that renderer is actually usable.

### Escalation

If keeping `net10.0` requires invasive cross-platform abstraction or materially distorts the existing renderer architecture, stop and return to planning. Do not silently change to `net10.0-windows`.

The expected implementation is a small explicit platform guard; broad cross-platform engineering is not M0013 scope.

## Consumer validation scenarios

Tier 4 uses a temporary consumer workspace and the installed package.

### Bootstrap

Prove:

```text
yadg init
```

creates the intended starter structure and does not overwrite owned paths.

### Strict authoring

Use a committed non-confidential Word/LibreOffice-compatible test template and source content sufficient to exercise representative 1.1 authoring.

At minimum:

```text
check
check --list
inspect styles
inspect template
build
```

must succeed in strict mode.

### YOLO authoring

Use a deliberate recoverable presentation mismatch such as an unavailable configured list presentation with a valid deterministic fallback.

Prove:

```text
check --yolo
build --yolo
```

succeed with visible degradation and useful authored output, while the corresponding strict command fails.

Do not use a semantic ambiguity/fatal case as the YOLO smoke.

### Word renderer

On the authoritative Windows locus, installed YADG must successfully finalize through real desktop Word using late-bound `Word.Application`.

### LibreOffice renderer

Installed YADG must successfully finalize through real LibreOffice.

### YOLO renderer fallback

Exercise one deterministic fallback using the packed tool, e.g.:

```text
requested LibreOffice with intentionally invalid --renderer-path
-> YOLO
-> actual Microsoft Word
```

Verify requested/actual renderer reporting and successful finalized output.

### Publish

Publish the current finalized DOCX using the installed package.

Also preserve the M0012 downstream-only guarantee: publication must not require re-validating current authoring sources or running Mermaid.
