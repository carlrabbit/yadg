## Goal

Make YADG authoring predictable for humans and agents. Use conventional Markdown relationships, preserve author-written link text, and configure generated numeric Word reference display once per workspace while keeping Word presentation template-owned.

## Target State

A YADG document uses one documented, narrow Pandoc-inspired Markdown profile, not a multi-dialect grammar. Normal Markdown fragment links are authored as links and retain their wording; explicit generated numeric references use existing `[@id]` syntax and configurable global rendering. Word fields remain updateable and correctly targeted. Existing projects retain numeric-only reference output by default.

## Scope

- Clarify and enforce the canonical authoring profile at the existing parser boundary.
- Add ordinary Markdown internal fragment links targeting explicit stable semantic IDs; emit correct Word-native hyperlinks and bookmarks.
- Add global semantic-reference formatting policy in workspace front matter.
- Refactor generated numeric reference emission as necessary for template-derived label-number presentations.
- Maintain existing placement, figure/table captions, heading rebasing, field and resilience behavior.
- Focused and real-renderer validation, installed-tool consumer validation, user-facing documentation, and blocking human review.

## Non-goals

- Implement the full Pandoc or MyST grammar, GitHub/GitLab-specific dialect handling, or general HTML anchors.
- Introduce implicit GitHub/GitLab heading-slug identity for semantic template targets.
- Change template placement tags, Word numbering definitions, caption prototypes, or renderer selection policy.
- Add per-reference style switches or MyST `[](#id)` generated-reference semantics.
- Add page-number references, localized label generation, full list nesting, or unsupported code-block conversion.
- Perform a blanket Markdown fallback redesign or broad release/documentation sync.

## Decisions and Constraints

1. **One canonical profile.** Existing supported CommonMark constructs, GFM pipe tables, and established Pandoc-style stable-ID attributes are the canonical syntax. `# Heading {#id}`, `![caption](file.png){#id}`, table `{#id ...}` on the following line, and fenced diagrams with existing attributes remain authoritative. No assertion of full Pandoc compatibility is permitted.
2. **Explicit identity.** A target intended for a template placement or a semantic Word reference needs an explicit stable ID. No implicit heading-slug matching, auto-generated public IDs, or HTML anchor association is introduced. IDs remain unique workspace-wide; duplicate IDs are fatal even with YOLO.
3. **Ordinary links retain words.** `[the model description](#liquidity-model)` displays exactly `the model description` in Word, is clickable to the referenced rendered target, and does not silently turn into the target title/number. Its text is not governed by numeric-reference formatting policy. Preserve ordinary character formatting and inline contexts.
4. **Separate generated references.** Existing `[@stable-id]` is the explicit generated numeric-reference form. It continues to produce only the configured reference representation, not surrounding prose. Authors write natural sentences such as `See [@model].` or `(see [@model])`. Do **not** reinterpret all local Markdown links as generated number references.
5. **Root front matter.** `YADG.md` schema version 1 adds:
   ```yaml
   references:
     headings: number
     figures: label-number
     tables: label-number
   ```
   Allowed heading mode: `number` only for this milestone. Allowed figure/table modes: `number` or `label-number`. Unspecified root or per-kind settings mean `number`, exactly the legacy `[@id]` behavior. Unknown reference keys/values are strict errors. Do not add `title`, `page`, locale strings, or per-reference options in this milestone.
6. **Template-owned presentation.** In `label-number` mode, the prefix (e.g. `Figure `, `Abbildung `), its punctuation and spacing, and numeric SEQ formatting must be derived from the actual selected caption prototype. The generated reference must be an updateable Word-native field/link combination; never hardcode English/German labels or compute a source-side numeral. If the prototype cannot unambiguously supply a coherent label+number target, strict mode reports a template capability error. Existing numeric-only behavior remains available.
7. **Strict target truth.** A reference or link to a semantic object must target exactly one actual emitted occurrence in the selected DOCX. A `{{content:id}}` insertion that omits a heading does not establish a heading target. Section numbers require real effective Word numbering; figures/tables require the relevant real caption/SEQ semantics for generated numeric references.
8. **Link resolution.** For local `#id` Markdown links, require a matching uniquely identified semantic object that actually renders in the output. Diagnose broken targets, ambiguous or non-rendered targets in strict `check` before falsely reporting success. External URL links and nonfragment URLs remain normal hyperlinks; do not route them through numeric-reference semantics. Preserve URL link text.
9. **YOLO.** It may visibly preserve unresolved generated-reference identity according to existing resilience rules, but cannot invent target identity, numbering, labels, or silently substitute a different object. Duplicate/ambiguous IDs remain fatal. For unresolved internal link targets, preserve authored visible link text without asserting clickability and report an explicit degradation.
10. **Compatibility.** No migration of existing Markdown or templates is required. In the absence of `references`, `[@id]` field behavior and resulting visible numbering match pre-milestone output. This new policy concerns reference rendering; it must not take over template-owned captions, styles, or static text.
11. **Execution boundary.** Source/project inspection and normal .NET commands permitted. Use existing Windows Word/LibreOffice toolchains and real application-produced fixtures. No persistent SDK/Office installation, host-wide changes, new remote services, or new CI infrastructure authorized. Missing required runtime blocks the corresponding validation/review; do not substitute synthetic-only proof and claim completion.

## Decision Preservation

The guiding distinction is **authored link wording vs generated numeric reference display**. `[@id]` is retained intentionally: a regular Markdown link is not an instruction to replace visible wording with a number. Global reference settings control generated reference representation, not ordinary hyperlinks. Word templates remain authoritative for labels, punctuation, SEQ fields and paragraph-number formats. This milestone is a deliberately constrained Pandoc-inspired profile, not a mandate to accept every Pandoc extension or every Markdown dialect.

## Acceptance Criteria

- **AC-01** — Document and implement one canonical, constrained Markdown authoring profile: CommonMark core, supported GFM pipe tables, and Pandoc-style `{#id}` on existing supported semantic objects; unsupported Pandoc extensions are not implicitly accepted.
- **AC-02** — Preserve existing explicit stable IDs for headings, tables, images and diagram fences, workspace-wide uniqueness and diagnostics; template placements and captions remain compatible.
- **AC-03** — Render ordinary `[author wording](#stable-id)` local Markdown links as clickable Word hyperlinks that preserve the exact authored visible wording and resolve to the unique emitted target.
- **AC-04** — Keep external links, file links and other ordinary Markdown hyperlink behavior distinct from generated numeric references; malformed/unresolved internal semantic targets fail in strict mode with actionable diagnostics.
- **AC-05** — Support root `YADG.md` schema-v1 `references` settings by semantic target kind: `headings: number`, `figures: number|label-number`, `tables: number|label-number`, with omission defaulting to the legacy numeric-only result.
- **AC-06** — Existing `[@id]` references use the configured generated representation and remain backward-compatible, with references emitted as actual updateable Word fields linked to the correct target, never a hardcoded cached numeral.
- **AC-07** — In `label-number` mode, labels, punctuation and numbering mechanics originate from the selected DOCX caption prototype rather than being invented, translated, or globally hardcoded by YADG.
- **AC-08** — Numeric generated references retain strict validation for unique rendered targets and actual heading numbering / figure-table SEQ structures; YOLO keeps unresolved identity visible without fabricating numbering.
- **AC-09** — `check --list`, strict `check`, `build`, and supported rendering flows consistently recognize and validate the new reference contract, including inline contexts previously accepting `[@id]`.
- **AC-10** — New and legacy reference forms are covered by source-to-DOCX inspection tests including correct bookmark/field/hyperlink structures, missing/duplicate targets, relative heading composition, and template-owned label behaviors.
- **AC-11** — Both real Microsoft Word and LibreOffice Writer finalize representative generated numeric references, update fields, and preserve authored hyperlink wording in realistic documents.
