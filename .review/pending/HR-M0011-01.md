# HR-M0011-01 — YADG 1.0.0 Release Readiness

## Purpose

Automated Tier 2–4 validation decides package identity, package contents, hashes, installed-tool behavior, renderer behavior, CLI/help assertions, and release evidence consistency.

The human review does not repeat those checks.

## Review subject

Review the corrected M0011 release candidate represented by the current M0011 release evidence, with attention to:

- `README.md`;
- the pending V1 entry in `CHANGELOG.md`;
- overall suitability to mark the validated candidate release-ready for a later separately authorized publication action.

Review tooling automatically binds the decision to the current repository revision and package SHA recorded in M0011 release evidence.

The reviewer does not manually provide or verify those machine values.

## Human acceptance

Answer:

1. Is the V1 README understandable and materially accurate for a prospective YADG user?
2. Is the pending V1 changelog/release description acceptable?
3. Given the automated release evidence, do you accept this exact candidate as release-ready?

## Decisions

```text
approved
changes-requested
rejected
```

Waiver is forbidden.

## Recording

The review command should require only human judgment and identity, for example:

```powershell
./eng/review.ps1 record -Milestone M0011 -Decision approved -Reviewer "<name>"
```

The tooling derives and records repository revision, package SHA, and runtime/evidence references automatically.

It must not require the human to transcribe:

- package hash;
- evidence hash;
- Word version;
- LibreOffice version;
- automated test results.

## Completion gate

M0011 completes only when:

```powershell
./eng/review-check.ps1 --milestone M0011
```

confirms that an approved record is bound automatically to the current corrected M0011 release evidence/package.
