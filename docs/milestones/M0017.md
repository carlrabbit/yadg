## Goal

Allow agents and humans to author ordinary technical Markdown without needing to avoid common constructs. Make Markdig the single Markdown syntax authority for both of its table extensions, while respecting YADG's template-first Word presentation boundary.

## Target State

YADG converts the everyday Markdown constructs listed below, correctly handles both Markdig pipe and grid tables, preserves existing ID/reference/template behavior, and validates through real applications and installed package use. YADG still advertises a constrained, documented Markdown profile rather than full Pandoc, GFM or MyST.

## Scope

- Both Markdig table dialects and proper AST-driven conversion, including grid-table paragraph content and representable merged cells.
- Fenced and indented literal code blocks, nested lists, blockquotes, inline strikethrough, and basic static GFM task markers.
- Make inline code ergonomic and template-owned by default.
- Core semantic-model / Word authoring changes as required, compatibility, focused/regression tests, real renderer and installed-package validation, docs and human review.

## Non-goals

- Full Pandoc/GFM/MyST dialect implementation, raw HTML, footnotes, math, definition lists, automatic heading slugs, HTML anchors, syntax coloring/highlighter producer, interactive checkbox controls, automatic source format conversion, or arbitrary rich content inside grid cells.
- Lists, nested tables, figures, blockquotes or fenced code inside grid table cells (these must be rejected truthfully).
- New template placement tags, invented figure/table labels, alterations to Word/LibreOffice renderer choice, generated reference syntax, or publishing behavior.
- Guide-system version migration or broad document synchronization (separate maintenance work).

## Decisions and Constraints

1. **Markdig is the syntax authority.** Use `UsePipeTables()` and `UseGridTables()` with existing recognized extensions. Table blocks/cells must be extracted from Markdig's parsed AST, not from scanning raw Markdown lines and splitting on `|`. For table metadata, retain source-compatible `{#id}` / `{#id caption="..."}` on the immediately following attribute line. Associate it with the immediately preceding parsed table and reject missing, duplicate or ambiguous IDs. Do not permit an attribute-line paragraph to leak into authored output. Implementer owns local metadata attachment mechanics.
2. **Canonical table syntax.** Pipe tables are default agent-authoring format for simple cells. Grid tables are the documented alternative for multiline paragraphs and merging. Both use the same YADG semantic table/placement/reference contract. Preserve existing caption prototypes and prepared tables.
3. **Table content.** In either dialect, preserve supported inline emphasis, strong, links, numeric refs and configured inline code. Grid-cell multiple paragraphs remain separate Word paragraphs. Preserve hard/soft breaks according to ordinary paragraph rules. Row/column spans when exposed by Markdig's table representation map to valid OOXML `gridSpan`/`vMerge` (or semantically equivalent Word structures), with consistent rectangular coverage. A construct that cannot be represented truthfully fails strict validation; no guessed spanning, cell flattening or lost cell content. Prepared-table row population retains prior behavior for rectangular single-paragraph cells; unsupported richer prepared-table shapes must fail explicitly rather than corrupt prototypes.
4. **Literal code.** Ordinary backtick/tilde fenced code blocks and indented code blocks become literal code content (not diagrams). Preserve source whitespace, indentation inside content, blank lines and line breaks in DOCX; a language token is non-authoritative metadata and is not displayed as code text. Existing explicit `mermaid`/`diagram` and opt-in text-diagram detection retain precedence. No syntax highlighter or external producer added.
5. **Nested lists.** Support ordered/unordered nesting and combinations with multiple nesting levels bounded by Word's existing numbering capabilities (maximum effective nine). Do not convert nesting into textual prefixes. One paragraph per list item plus nested child lists; unrelated multi-paragraph list-item content remains unsupported with a diagnostic. Numbering and layout from template styles/prototypes; do not invent label formats. Beyond supported effective level, strict error before output mutation.
6. **Blockquotes.** Support paragraphs and nested blockquotes with normal inline semantics; use a template-defined presentation role or existing compatible prototype. No synthetic decorative quotation marks, admonition labels or source deletion. Quotes containing unsupported block types fail explicitly.
7. **GFM small extensions.** Support `~~strike~~` through the Markdig extension and emit strike formatting. Support checkbox task list markers (`[ ]`, `[x]`, `[X]`) only in list-item position; emit static checkbox glyphs/checked state, not interactive Word content controls. Template owns paragraph/list styling. Preserve surrounding authored list content. Plain occurrences outside list context retain ordinary text semantics.
8. **Inline code.** New default `markdown.codeInline: style`, with template-owned character-style resolution through the existing presentation role. If the style is unavailable, strict must diagnose the missing required template capability; explicit `ignore` preserves literal text without code styling and explicit `error` continues rejecting inline code. Existing workspace configs are not rewritten. Existing known direct style bindings/aliases and renderer-neutral authoring boundary remain in effect.
9. **Thematic breaks.** Retain current `markdown.thematicBreak` error/ignore options; no new horizontal-rule presentation in this milestone.
10. **Compatibility.** Preserve explicit stable IDs, link wording for `[text](#id)`, generated Word `[@id]` number/label-number semantics, template-owned headings/captions/styles, diagram fences, figure semantics, strict vs YOLO diagnostics, and M0016 behavior. Do not claim unsupported Pandoc attributes or GFM features as accepted.
11. **Resilience.** Strict mode fails for unsupported or ambiguously representable constructs; YOLO may preserve visible literal content or degradation placeholders only under existing truthful recovery rules. It must not silently discard text, invent table geometry, overwrite an existing good output on error, or pretend unsupported rich grid content was faithfully rendered.
12. **Environment and implementation authority.** Use existing YADG Windows/Word/LibreOffice tests, verified application-produced fixtures and .NET SDK. Source code/tests can be changed within this semantic contract. Executor may use existing tools and isolated temporary test paths; no persistent provisioning or infrastructure changes. Lack of a required real-runtime/review capability leaves the milestone BLOCKED rather than passed by substitutes.
13. **Milestone sequencing.** Apply after the M0016 semantic links/reference implementation is merged (or correctly incorporated in the worktree); do not assume PR number establishes completed human review. Existing M0016 unfinished review remains an independent closure obligation, not something this milestone can waive.

## Acceptance Criteria

- **AC-01** — Parse pipe tables and Pandoc-style grid tables using Markdig Table/TableRow/TableCell AST as sole syntax authority; eliminate YADG handwritten line splitting/table-row recognition for semantic extraction.
- **AC-02** — Retain simple existing pipe-table syntax, stable IDs/captions, ordering, section/content inclusion, generated tables, prepared row population and semantic references without source migration.
- **AC-03** — Correctly preserve pipes escaped with backslashes and pipe characters inside code spans in table cells; nested inline emphasis, links, references, line-break semantics match ordinary paragraphs.
- **AC-04** — Accept rectangular grid tables with literal cell text, inline formatting and multiline cell paragraphs without flattening paragraph boundaries; emit valid table-cell paragraphs in DOCX.
- **AC-05** — Support Markdig-represented horizontal and vertical merged grid cells (colspan and rowspan) in generated DOCX tables, preserving logical cell coverage and Word merge structures.
- **AC-06** — Reject grid cells with unsupported contained block types (including lists, headings, nested tables, fenced blocks) with actionable location/construct diagnostics; never discard or silently flatten content.
- **AC-07** — Support fenced and indented literal code blocks as content in ordinary sections, with exact text/indentation/line boundaries preserved; language info may be retained as metadata but does not trigger an external highlighter.
- **AC-08** — Support nested ordered and unordered lists, including mixed types, preserving nesting levels and sequential list semantics in DOCX using template-owned styles/numbering/prototypes.
- **AC-09** — Support CommonMark blockquotes with paragraphs, inline emphasis/links and nested blockquotes, using template-owned presentation without inserting invented label text.
- **AC-10** — Support GFM strikethrough as Word strike formatting, GFM task list markers as static marked/unmarked checkbox glyphs with appropriate list semantics, and no interactive Word content controls.
- **AC-11** — Make inline code usable by default with `markdown.codeInline: style` and a defined template-owned character-style resolution; explicit legacy `error` and `ignore` settings remain accepted and documented.
- **AC-12** — Strict checks and YOLO behavior distinguish unsupported content and absent template presentation: never silently erase valid authored Markdown; YOLO uses existing visible-degradation policy without fabricating content or structure.
- **AC-13** — Preserve heading IDs, figures, link wording, `[@id]` numeric references, diagrams and template placement semantics introduced through M0016; no broad Pandoc/GFM compatibility claim.
- **AC-14** — Add focused source-to-OpenXML and negative regression evidence for both table dialects, merges, escaped pipes, code, nested lists, quotes, strikethrough and task lists.
- **AC-15** — Real Word and LibreOffice finalization/reopen preserves representative new constructs and template-owned layout without repair errors.
