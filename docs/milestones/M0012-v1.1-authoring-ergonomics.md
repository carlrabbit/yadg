## A. Trusted local workspace, not a filesystem sandbox

YADG is a local user-scope CLI operating on a workspace deliberately selected by that user. The workspace is trusted input. YADG does not attempt to establish a hostile-filesystem sandbox around it or defend the user from intentionally created filesystem links.

This does not remove ordinary correctness boundaries.

### File links

Do not reject an otherwise usable file merely because it has a symbolic-link/reparse-point attribute. This applies to ordinary file inputs such as:

- `YADG.md`;
- Markdown source files;
- DOCX templates;
- figure assets;
- finalized publication inputs.

If normal OS file APIs expose the linked file and its content satisfies the relevant YADG contract, it may be used. Do not resolve the final symlink target merely to enforce a second physical-containment boundary.

### Explicit workspace directories

The selected workspace root may itself be reached through a link/junction. Likewise an explicitly addressed conventional directory such as `YadgTemplates` may be a linked/junction directory and may be accessed for its defined top-level operation.

### Recursive discovery

Recursive source discovery is different: blindly following linked directories can create cycles, duplicates, or unbounded scans.

When recursive Markdown discovery encounters a linked/reparse directory below the discovery root:

```text
do not recurse into it
```

This is not an error. Emit at most a non-fatal warning explaining the linked directory was skipped.

No acceptance gate requires Windows symbolic-link creation privilege. A link/junction runtime test may be capability-gated; inability to create one on the implementation host is not a milestone failure.

### Lexical workspace containment remains

YADG still rejects explicit asset paths that lexically escape the workspace, e.g.:

```text
../../outside.png
```

This is a portability/reproducibility rule, not a hostile-filesystem sandbox. Do not canonicalize symlink targets to enforce physical containment.

Remote/data URI assets remain unsupported unless another product contract adds them.

### Discovery pruning

Recursive Markdown discovery must prune non-source directories before descending into them. At minimum do not recurse into:

```text
YadgTemplates
YadgPreWords
YadgWords
YadgPdfs
directories whose path segment begins with "."
```

This avoids scanning `.git`, `.execution`, `.review`, generated output trees, and similar locations merely to filter files later.

Nested `YADG.md` detection applies to the actual discoverable source tree, not to deliberately excluded directories.

## C. Publishing must be downstream-only

The architecture already defines:

```text
YadgWords/*.docx
    |
    | publish
    v
destination
```

The command must enforce that boundary operationally.

### Explicit CLI destination

When `--publish-path` is supplied, `publish` must not:

- invoke the normal authoring `WorkspaceLoader`;
- parse Markdown sources;
- inspect/validate DOCX templates;
- validate authoring figures;
- execute Mermaid or another external content producer;
- require current authoring inputs to be valid.

It needs only the selected workspace root, finalized `YadgWords` inputs, the explicit destination, and publication-specific preflight.

An already-finalized artifact remains publishable even if current authoring sources/templates have since become invalid.

### Configured destination

When `--publish-path` is absent, YADG may read `YADG.md` only as needed to obtain:

```text
publish.path
```

Publication must not trigger unrelated authoring validation or external producer execution.

If configuration cannot be parsed sufficiently to obtain a valid destination, publication fails with a publication/config diagnostic.

### Producer non-execution

Add a test proving `publish` does not execute a configured Mermaid producer. Use a sentinel producer configuration whose invocation would be observable; publication from existing finalized DOCX must succeed without invoking it.

### Retained publication behavior

Keep:

- CLI destination precedence;
- workspace-relative configured destination;
- reserved generated-directory protection;
- top-level `YadgWords/*.docx` only;
- same-name destination replacement;
- unrelated destination files preserved;
- no implicit build/render;
- no PDF publication;
- no stale destination cleanup.

## D. Complete finalized-output ownership

Generated workspace directories are YADG-owned artifact sets, not mixed user-content folders.

The previous correction established this for `YadgPreWords`. Apply the same freshness principle to rendering.

### Successful render result set

For actual LibreOffice rendering:

```text
YadgWords/*.docx
YadgPdfs/*.pdf
```

must correspond exactly to the current successfully rendered `YadgPreWords/*.docx`.

For actual Microsoft Word rendering:

```text
YadgWords/*.docx
```

must correspond exactly to the current successfully rendered PreWords, and `YadgPdfs` must contain no stale PDFs from an earlier LibreOffice render.

This also applies when YOLO requested one renderer but successfully fell back to the other.

These must not happen:

```text
previous render: A.docx + B.docx
latest PreWords: A.docx
latest render succeeds
YadgWords: A.docx + stale B.docx
```

or:

```text
previous LibreOffice render: A.docx + A.pdf
latest actual renderer: Word
render succeeds
YadgPdfs still contains stale A.pdf
```

### Commit behavior

Use staging/commit or equivalent complete result-set replacement so cleanup occurs only after the actual renderer successfully produced its intended set.

A failed render does not claim a new finalized result set. Preserving the prior committed result set on failure is preferred and consistent with the existing staged fallback design.

Do not delete the old result set before renderer success is known.

### Publishing implication

Because `publish` copies current `YadgWords` without rebuilding, finalized-output freshness is a renderer responsibility.

## E. Tool-owned directory contract

Update user/engineering docs to make artifact ownership explicit:

```text
YadgTemplates  = user/template input
YadgPreWords   = YADG-generated authored set
YadgWords      = YADG-generated finalized DOCX set
YadgPdfs       = YADG-generated renderer-specific PDF set
```

Users should not place unrelated persistent files in generated artifact directories.

This permits complete result-set replacement without complex preservation rules.
